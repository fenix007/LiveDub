# LiveDub — живой перевод и озвучка любой вкладки

Звук любой вкладки Chrome → распознавание речи Deepgram (стриминг) → перевод
встроенным переводчиком Chrome (on-device, бесплатно), Gemini или другим LLM.

```
Вкладка ──getDisplayMedia──► AudioWorklet (PCM 16 кГц, чанки 40 мс)
                                   │  WebSocket напрямую, JWT на 30 с
                                   ▼
                            Deepgram nova-3 ──► interim / final / speech_final
                                   │               │
                                   ▼               ▼
                           черновой перевод   окончательный перевод
                              Chrome / Gemini / LLM
```

Сервер (`server.js`) раздаёт страницу, выдаёт временные токены Deepgram и переводит
через выбранный движок. Gemini работает через отдельный долгоживущий Python-процесс
с [gemini-gateway](https://github.com/NickZaitsev/gemini-gateway): он переключает ключи,
соблюдает лимиты и повторяет временно неудачные запросы. Ключи не отправляются в браузер.
Аудио идёт из браузера в Deepgram напрямую. Во время отсутствия аудиоданных браузер
отправляет текстовый `KeepAlive` каждые 4 секунды, чтобы соединение не закрывалось.

Под подсказкой на странице показывается статистика последних 50 Gemini-запросов:
медиана (p50), p95, количество ответов дольше 5 секунд, ошибок и ожидающих запросов.
Отдельно указан p95 окончательных переводов. Подробности доступны в `/api/stats`:
тип запроса (черновик/финал), время в очереди Python worker и время внутри
`gemini-gateway`, модель и обезличенная метка ключа. Тексты реплик и ключи в статистику
не попадают. Данные хранятся только в памяти сервера и сбрасываются при перезапуске.
Если доступен встроенный переводчик Chrome, по умолчанию выбирается режим
«Chrome черновик + Gemini финал»: промежуточный текст переводится локально,
а Gemini получает только окончательные реплики. В режиме «Gemini (сервер)»
одновременно отправляется не больше одного черновика; сервер дополнительно
ограничивает их частоту (по умолчанию 6 в минуту при `GEMINI_RPM=15`).
Окончательные переводы этим ограничением не задерживаются. Число пропущенных
черновиков видно в статистике.

DeepSeek доступен как отдельный движок и в режиме «Chrome черновик + DeepSeek финал».
Для короткого перевода сервер явно отключает thinking и ограничивает время запроса
десятью секундами. При ошибке или таймауте в смешанном режиме финальную фразу
переводит Chrome. `/api/stats` показывает для DeepSeek те же p50/p95 и ошибки,
чтобы сравнить задержки с Gemini на реальных репликах. Статистика также хранится
только в памяти и не содержит тексты или ключи.

Yandex Translate доступен как отдельный движок и в режиме «Chrome черновик + Yandex
финал». В этой сборке он выбирается по умолчанию, чтобы сравнить задержку и качество
с DeepSeek; другой движок можно выбрать вручную. Уже добавленный ключ SpeechKit
подходит, если у сервисного аккаунта есть роль `ai.translate.user`, а у ключа —
область действия `yc.ai.translate.execute`. При необходимости задайте отдельный
`YANDEX_TRANSLATE_API_KEY` в `.env`. Для API-ключа сервисного аккаунта `folderId`
не нужен. В `/api/stats` → `yandexTranslate` видны p50/p95 и ошибки без текстов
и ключей. Таймаут задаётся через `YANDEX_TRANSLATE_TIMEOUT_MS` (по умолчанию 5 с).

Включите «Озвучивать перевод», чтобы слышать перевод во время речи. Синтез речи
выполняет браузер через Web Speech API; отдельный TTS-ключ не нужен. Голос выбирается
по целевому языку, локальные голоса предпочитаются для меньшей задержки. Озвучка
выключена по умолчанию. Из черновика произносится устойчивое начало без последнего
слова; после финального перевода добавляются новые слова. Если уже произнесённое
начало исправилось, новый вариант остаётся на экране: повторять всю фразу вслух
приложение не будет. В смешанных режимах браузерный голос продолжает черновик Chrome,
поэтому его формулировка может отличаться от финала Gemini или DeepSeek. SpeechKit
в этих режимах озвучивает только финальный перевод, совпадающий с текстом на экране;
начало озвучки при этом ждёт ответа финального переводчика.
При отставании старые ожидающие фразы пропускаются. Под статистикой запросов показаны
время ожидания озвучки, число таких пропусков и исправлений уже произнесённого начала.

Для более естественного русского голоса подключите Yandex SpeechKit: создайте
API-ключ сервисного аккаунта с правом `yc.ai.speechkitTts.execute`, добавьте
`YANDEX_SPEECHKIT_API_KEY` в `.env` и перезапустите сервер. При переводе на русский
можно выбрать SpeechKit и голос Марина, Алёна, Джейн, Филипп, Ермил или Захар.
Ключ остаётся на сервере. Устойчивые фрагменты чернового перевода сразу
отправляются на синтез; MP3 передаётся в браузер по мере получения. Это
короткие запросы к API v1, поэтому задержка зависит от времени генерации
каждого фрагмента, а не постоянная gRPC-сессия API v3.
Задержки SpeechKit и события очереди доступны в `/api/stats` → `tts` и в
серверном логе с префиксом `[tts]`. В журнал попадают время, длина фрагмента,
размер очереди и причина пропуска, но не текст перевода и не ключи.

## Chrome-расширение LiveDub (без сервера)

Папка `extension/` — тот же конвейер в виде расширения MV3. Сервер не нужен:
ключи вводятся на странице настроек расширения и хранятся в `chrome.storage.local`
(не синхронизируются). Запросы идут из расширения напрямую в API.

```
иконка → боковая панель ── tabCapture ──► AudioWorklet PCM 16 кГц ──► Deepgram (WS, ключ в subprotocol)
                │                 └─► звук вкладки снова в колонки (при озвучке приглушается)
                ├─ черновик: Chrome on-device / Yandex Translate / DeepSeek
                ├─ финал:    DeepSeek / Yandex Translate / Chrome
                ├─ озвучка:  браузер или Yandex SpeechKit
                └─ субтитры поверх страницы (content script, работает и в полноэкранном режиме)
```

1. `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» → папка `extension/`.
2. После установки откроются настройки: введите ключ Deepgram (обязательно), DeepSeek и Yandex Cloud
   (необязательно) и нажмите «Проверить». Позже настройки открываются через «Параметры» расширения
   или ссылку «Ключи API» в панели.
3. Откройте вкладку со звуком, нажмите на иконку расширения, затем «Переводить эту вкладку».

Для Yandex нужен API-ключ сервисного аккаунта с ролями `ai.translate.user` (Translate) и
`ai.speechkit-tts.user` (SpeechKit). Folder ID можно не указывать, если ключ принадлежит сервисному аккаунту.
Закрытие боковой панели останавливает перевод. Архив для передачи: `make extension-zip`.

## Запуск веб-прототипа

```bash
make setup                # создать .env, затем вписать DEEPGRAM_API_KEY (права Member+)
make start                # нужен Node 20.6+; остановка: Ctrl+C
```

Для Chrome и OpenAI-совместимого LLM зависимости не нужны, `npm install` не требуется.
Для Gemini установите Python 3.10+ и выполните `make gemini-deps`. Затем добавьте в `.env`:

```dotenv
GEMINI_API_KEYS=ключ1,ключ2
GEMINI_MODEL=gemini-3.1-flash-lite
```

Для одного ключа можно использовать `GEMINI_API_KEY`. Настройки `GEMINI_RPM`,
`GEMINI_TPM`, `GEMINI_RPD` и другие параметры `gemini-gateway` также читаются из `.env`.
Лимит черновиков задаётся отдельно через `GEMINI_DRAFT_RPM`. После запуска при
доступном Chrome Translator автоматически выбирается режим «Chrome черновик + Gemini финал»;
иначе — «Gemini (сервер)». Реальные ключи нужно получить самостоятельно и хранить
только в `.env`.

Для DeepSeek добавьте в `.env` и перезапустите сервер:

```dotenv
DEEPSEEK_API_KEY=ваш_ключ
DEEPSEEK_MODEL=deepseek-flash
```

После обновления вкладки выберите «Chrome черновик + DeepSeek финал» либо
«DeepSeek (сервер)». Таймаут можно изменить через `DEEPSEEK_TIMEOUT_MS` (миллисекунды).
Ключ DeepSeek в браузер не отправляется.

`make setup` сохраняет существующий `.env`.
`make start` и `make dev` также создают `.env`, если его ещё нет.
Запуск через `npm start` по-прежнему доступен.

### Команды Make

| Команда | Назначение |
| --- | --- |
| `make` / `make help` | Список команд |
| `make setup` | Подготовить `.env` без перезаписи существующего файла |
| `make start` / `make run` | Запустить сервер |
| `make dev` | Перезапускать сервер при изменении серверного кода |
| `make gemini-deps` | Установить `gemini-gateway` в `.venv` |
| `make check` | Проверить синтаксис и тесты перевода/PCM без обращения к API |

После изменения `public/index.html` обновите вкладку браузера. После изменения `.env`
перезапустите сервер. Порт задаётся в `.env` (по умолчанию `3000`) или при запуске:
`make start PORT=3001`. Другой исполняемый файл Node можно выбрать через `NODE=/path/to/node`.

Открыть http://localhost:3000 в **Chrome или Edge на десктопе** → «Захватить вкладку» →
выбрать вкладку → включить **«Также поделиться звуком вкладки»**.

## Ограничения
- Звук вкладки через `getDisplayMedia` есть только в Chromium на десктопе; Firefox и Safari его не отдают.
- Translator API — Chrome 138+; при первом запуске пары языков скачивается модель (прогресс в статусе).
  Качество ниже LLM, зато перевод занимает десятки миллисекунд и бесплатен.
- Каждый запуск — диалог выбора вкладки. Без диалога — только расширение с `chrome.tabCapture`.
- Окончательный перевод закрепляется после паузы 300 мс, конца предложения или 30 слов.
  Для длинной реплики сначала показывается черновой перевод устойчивых слов из
  промежуточного распознавания. Черновик обновляется не чаще одного раза в 1,2 с и
  заменяется окончательным переводом после завершения фразы.
